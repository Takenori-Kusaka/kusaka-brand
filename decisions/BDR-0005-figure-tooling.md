# BDR-0005: 一目でわかる図は手書き SVG テンプレートで描き、構成図は D2 のまま残す

## ステータス

採用(2026-10-12)

## コンテキスト

publishing-hub の図は D2 + TALA で、構成図としては読めるが「一目でわかる」キービジュアル(参照: モンスターラボのスクラムの一枚絵)にはならない。D2 は自由形状・曲線のループ・自由座標・大きな題を持てない(`research/03-catchy-diagram-research.md` 5a)。再現性(ソースと PNG のハッシュの検査)は保ちたい。

## 決定

- 図を 3 層に分ける。**キービジュアル**と**節図**は手書き SVG テンプレート(トークンの占位子 `{{color.ai.800}}`)を `@resvg/resvg-js` で描く。**構成図**は D2 + TALA のまま、`dist/d2/theme.d2` でブランドの色を当てる
- 描画器(`scripts/render-svg.mjs`)は同梱フォントだけを使い(`loadSystemFonts: false`)、OS に依らず同じ画素を出す。メタ情報にソース・トークン・フォント・出力のハッシュを書き、利用側の検査(S1〜S6)が手差し替えとブランドの更新漏れを止める
- 主ラベルの最小フォントサイズ ≥ 自然幅 / 32。補助ラベルは `data-tier="secondary"` で規則から外し、本文に同じ情報を書く
- 記号は自作の線画 3 種(人・チップ・印)。外部のアイコン集は使わない(ライセンス表示の義務と、線幅の不一致を避ける)
- 14 条の作成規則(`brand/05-figures.md`)

## 検討した選択肢

| 案 | 採らなかった理由 |
| --- | --- |
| D2 の classes + theme-overrides + grid で寄せる | 箱と線は揃うが、円環・レーン・大きな題が作れない。「きれいな箱と線」止まり |
| Satori(JSX → SVG) | 文字の折り返しに強く OGP 用途の第一候補だったが、オーバルや曲線の矢印を JSX で書きにくい。文字主体の図(原則の札)では将来の候補として残す |
| Playwright(HTML/CSS → PNG) | CSS の表現力は最大だが、OS・ブラウザ版で画素が変わり、ハッシュの検査ができない。Docker 固定の運用コストが個人には重い |
| Excalidraw | Node 単体で書き出せない(DOM 前提)。手描き風は不要 |
| 生成画像(Gemini) | 文字を入れられず、構造の正確さを担保できない。挿絵に限る |

## 根拠の水準

- Zenn の本文幅と縮小率は 2026-09-21 の実測(publishing-hub `docs/diagrams.md`)
- 「主ラベル ≥ 幅/32」は、電話(360px)で 11〜12px を下限とする判断。実証ではない(暫定。読者の反応で見直す)
- resvg の出力のバイト一致は手元(Windows)で確認。CI(Linux)での一致は未確認(暫定)

## 影響

- publishing-hub に `images/<題材>/*.svg` と `scripts/figures/render-svg.mjs`、検査 S1〜S6 を追加
- process-compass は描画器を持たず、SVG・PNG・メタ情報の 3 点を置き、ハッシュだけを検査する
