# BDR-0004: 声を「率直・根拠を示す・静か・翻訳者」の 4 属性で固定し、トーンを媒体の行列で変える

## ステータス

採用(2026-10-12)

## コンテキスト

既存の原稿には規約(ですます、煽りの禁止、複数称の禁止、冒頭で名乗る)が検査として存在するが、「どういう人が書いているか」の定義がなかった。日本語の公開デザインシステムに、声とトーンを章として持つ例は見つからなかった(`research/01-brand-systems-survey.md` 1〜2 章)。

## 決定

- 声は「X だが Y ではない」の 4 組(`brand/00-foundation.md` 3 節)。率直だが冷たくない / 根拠を示すが衒学的でない / 静かだが無関心でない / 翻訳者だが代弁者でない
- トーンは媒体 × 属性の強度の行列(`brand/03-voice-and-tone.md`)。深刻な内容ほど人格を薄く、対話的な場ほど濃く(Monzo 型)
- 事実と意見の体裁を分ける。事実は修飾語なし + 出典、意見は「本節は著者の解釈です」か段階語彙(IPCC の確信度を文末に移す)、規範は ISO/IEC Directives の動詞形の日本語(しなければならない / することが望ましい / してもよい / できる)
- 一人称は、標準と正本では「本標準」「本書」、派生物では「私」。「私たち」「弊社」は使わない
- 冒頭 3 行で何の話かを名乗る。煽らない。感嘆符は 1 ページ 1 つまで。時間を明示する

## 検討した選択肢

| 案 | 採らなかった理由 |
| --- | --- |
| Microsoft 型の 3 原則(warm / crisp / ready to help) | 製品の UI 文言向け。長文の技術文書と標準には「根拠」と「翻訳」の軸が要る |
| Mailchimp 型の 4 属性(Plainspoken / Genuine / Translator / Dry humor) | 最も近いが、乾いたユーモアは本人の「迷ったら真顔」と合わない。Translator は借りた |
| 声を定義せず検査規則だけで運用する | 規則は「書いてはいけないこと」しか言えず、新しい媒体(登壇・稟議)で判断できない |

## 影響

- publishing-hub の AGENTS.md と `docs/social-editorial-guide.md` は、この文書を上位の規約として参照する(矛盾があれば AGENTS.md を直す)
- 留保の段階語彙は、process-compass の根拠水準マーク(ADR-0026)と併用する。マークは値に、語彙は文末に
