# 02 書体と組版 ── UD ゴシックを骨格に、本文とコードを同族で揃える

決定は `decisions/BDR-0003-typefaces.md`。根拠は `research/01-brand-systems-survey.md` 3 章。

## 1. 書体(3 つ)

| 役割 | 書体 | 太さ | 理由 |
| --- | --- | --- | --- |
| **見出し・図の文字** | BIZ UDPGothic | 400 / 700 | モリサワの UD(ユニバーサルデザイン)書体。字面が大きく、似た英数字を区別しやすい。「誰にでも」でなく「より多くの人に」。製造現場の帳票・掲示と同じ系統。OFL 1.1 で画像焼き込み・Web 配信・同梱ができる |
| **本文** | Noto Sans JP | 400 / 700 | 最も広く配布され、60 年の入手性が最も高い。デジタル庁デザインシステムが採用。長文の可読性 |
| **コード・識別子・数値の列** | UDEV Gothic | 400 / 700 | BIZ UD ゴシックと JetBrains Mono の合成。**見出しと同じ骨格**で、全角スペースの可視化とスラッシュ付きゼロを持つ |
| 欧文 | (別書体を持たない) | ── | 和文書体の欧文グリフを使う。欧文だけ別書体にすると混植のアキと高さが揃わない |

代替(フォントが使えない環境): 見出し → Noto Sans JP 700、本文 → システムのゴシック(游ゴシック、Meiryo、Hiragino Sans)、コード → Consolas / Menlo。

Web では `fonts/` の woff2 化は利用側で行い、サブセットにしたら名前を変えます(OFL の Reserved Font Name)。

## 2. サイズと行間

| 要素 | サイズ | 行間 | 字間 |
| --- | --- | --- | --- |
| 本文 | 16px(1rem)。14px 未満は使わない | 1.9(1.7〜2.0 の範囲で、本文は広く) | 0.01em |
| 見出し h1 / h2 / h3 | 1.75 / 1.375 / 1.125rem | 1.4 | 0.02em |
| 補助文 | 0.875rem | 1.7 | 0 |
| コード | 0.9375rem | 1.6 | 0 |
| 図のラベル | 自然幅 / 32 以上(`05-figures.md`) | ── | ── |

行間の数値は実証ではなく、JLReq が数値を定めないこと、デジタル庁が本文 1.5 倍以上(快適な本文で 175%)とすることを踏まえた判断です。文字サイズが大きいほど最適な行間は狭くなる(群馬大学 2014)ので、見出しは 1.4 です。

## 3. 和欧混植

- **和欧間のアキ**: 原稿に空白文字を打たない。アキは組版エンジン(CSS `text-autospace`、ブラウザの既定)に任せる。ただし、このリポジトリ群の既存の原稿は「AI 協調ループ」のように半角スペースを打つ表記で統一されており(publishing-hub の用語辞書)、**原稿内で統一されていることを優先**する。移行は辞書の改訂で行う
- **数字**: 横書きは半角の算用数字。4 桁以上は 3 桁ごとにコンマ。概数と語を構成する数は漢数字(二十余人、一つ、二者択一)。数字と助数詞は密着(3つ、2024年、5GB)。文書内で全角・半角を統一する(公用文作成の考え方)
- **句読点**: 「、」「。」。横書きでも「，」「．」は使わない
- **括弧**: 補足は（）、引用・強調・ファイル名は「」、「」の中は『』。UI のラベルは［］。コードはバッククォート。英語文脈の引用符は “ ”
- **区切り**: ・ ／ ： は全角で前後にアキなし。範囲は「〜」。ダッシュは「──」(U+2500 を 2 つ)か「 ― 」(U+2015)。「—」(U+2014)は使わない

## 4. 斜体・太字・強調

| 手段 | 使う場面 | 使わない場面 |
| --- | --- | --- |
| **斜体** | 使わない | 日本語書体は斜体を持たず、合成斜体は読みにくい(デジタル庁)。英語でも使わない(GOV.UK)。書名は『』、語としての語は「」 |
| **太字** | UI の要素名、手順の中で押すもの、表の見出し | 強調。強調は「」か、文頭に要点を置くか、見出しで代える |
| **圏点** | 縦組の強調だけ | 横組 |
| **下線** | リンクだけ | 強調 |
| **色** | 意味(人が触る場所、暫定、却下)だけ | 強調 |

「太字で目立たせる」癖は、太字の情報量をゼロにします。1 ページに太字の語が 5 つ以上あれば、構成を直します。

## 5. 意味別の体裁

事実と意見の体裁を分けるデザインシステムは見つかりませんでした。最も厳密な先例(IPCC の不確かさの扱い、ISO/IEC Directives の動詞形、BBC の personal view の明示)を日本語に移し、既存の根拠水準マークに接続します。

| 意味 | 体裁 | 例・規則 |
| --- | --- | --- |
| **事実**(出典あり) | 平文。修飾語なし。出典リンクを添える | 「F1 のピット作業は、18〜20名が2秒以下で終えます」+ 出典 |
| **著者の解釈・意見** | 節の冒頭に「本節は著者の解釈です」。留保語は段階語彙から選ぶ(下表) | 「〜と考えています」「〜の可能性が高い」 |
| **暫定・未検証** | `:::caution[暫定 EV-NNNN / 見直し YYYY-MM]`(process-compass)または黄土の囲み(サイト) | 識別子と見直し期限を必ず付ける |
| **規範の強さ** | しなければならない / することが望ましい / してもよい / することができる | 「べき」を規範語として使わない(ISO/IEC Directives Part 2、JIS Z 8301) |
| **引用** | 「」または引用ブロック。原文のまま。出典必須 | 訳した文を引用符に入れない |
| **注意・警告** | コールアウト。感嘆符を使わない | 失敗の説明に「！」を付けない |
| **コード・ファイル名・コマンド** | バッククォート。引用符で囲まない。複数形・動詞化しない | `process.config.json` |
| **UI のラベル** | ［設定］のように［］ | 英語文脈なら太字 |
| **外来語** | 内閣告示「外来語の表記」第 1 表。-er / -or / -ar は長音(ユーザー)。固有名詞は英字の正式名(GitHub、Claude Code) | 「ウェブ」は本文、固有名詞中は Web |
| **時間** | 「2026-10-12 時点」のように時点を書く。「最新」「現在」「新しい」を単独で使わない | AI の能力に関する記述は時点を必ず併記 |

### 留保の段階語彙(IPCC の確信度を日本語の文末に移したもの)

| 確からしさ | 文末 |
| --- | --- |
| 事実として述べる | 〜です。〜します(出典あり) |
| 高い確信 | 〜と考えています。〜とみています |
| 中程度 | 〜の可能性が高い。〜とみられます |
| 低い | 〜かもしれません。〜の可能性があります |
| 確かめていない | 確かめていません。測っていません(1 回だけ事実として書く。定型文として繰り返さない) |

## 6. 文体

- 本文は「ですます」。箇条書きと表は「である」か体言止め(textlint preset-ja-technical-writing の既定と同じ)
- 一人称: 標準・正本は「本標準」「本書」。派生物(note・SNS)は「私」。「私たち」「弊社」は使わない
- 1 文は 100 字まで。読点は 1 文に 3 つまで。漢字は 6 字以上続けない
- メタ談話(「読者は〜と思うでしょう」「本節では〜を扱います」)を書かない。問いは疑問文で置く
