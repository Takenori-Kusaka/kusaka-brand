# 05 図 ── 一目でわかる図と、正確な図を分ける

根拠は `research/03-catchy-diagram-research.md`、決定は `decisions/BDR-0005-figure-tooling.md`。

## 1. 3 つの層

| 層 | 目的 | 作り方 | 規則 |
| --- | --- | --- | --- |
| **キービジュアル** | 3 秒で主張が伝わる一枚絵。記事の冒頭、OGP、SNS、サイトのヒーロー | 手書き SVG テンプレート(トークンの占位子)→ `render-svg.mjs` → PNG | 本節の 14 条。主ラベル ≥ 幅 / 32 |
| **節図** | 記事の節・標準の章に 1 枚。構造と原則 | 同上 | 同上。自然幅 720px |
| **構成図** | コンポーネント・コンテナ・データの流れを正確に | D2 + TALA(`dist/d2/theme.d2` を読み込む) | C4 の規範(凡例を置く、色を抜いても通じる)。自然幅 ≤ 480px(Zenn) |

Mermaid は本文中の簡易なフロー(ノード 8 個以内)にだけ使い、構成図とキービジュアルには使いません。

## 2. キービジュアルの 14 条

| # | 規則 |
| --- | --- |
| R1 | 要素は 5〜9 個。束ねた塊は 4 つ以下 |
| R2 | 1 枚 1 主張。主張を一文で書けない図は作らない |
| R3 | 形が主張を語る(円 = 繰り返し、レーン = 人が触る場所、階段 = 段階)。ラベルは確認に使う |
| R4 | 読み順は 1 本。左→右、上→下、時計回りのどれか。分岐は 1 か所まで。開始点を示す |
| R5 | 強調色は丹 1 色。丹は「人が触る場所」にだけ |
| R6 | ラベルは 8 文字 × 2 行以内。説明文を図に入れない |
| R7 | 凡例を置かない。凡例が要る図は構成図として作る |
| R8 | 題と一文の要約を画像の中に置く(SNS で切り抜かれても主題が残る) |
| R9 | 記号は 1 セット・1 線幅(自作の線画: 人・チップ・印)。写実のイラストと混ぜない |
| R10 | 余白は面積の 3 割以上。要素の間隔は要素の高さ以上 |
| R11 | **主ラベルの最小フォントサイズ ≥ 自然幅 / 32**(1200px で 38px、720px で 23px。幅 390px の電話で 11〜12px)。補助ラベル(`data-tier="secondary"`)は本文に同じ情報を書くことを条件に小さくてよい |
| R12 | 色を抜いても意味が通る(白黒で確かめる) |
| R13 | 比喩は主張と一体のものだけ(ピットレーン)。飾りの絵を入れない。比喩の数値(2 秒)を借りない |
| R14 | alt は 1〜2 文で識別と長い説明の所在を書き、長い説明は本文に書く(W3C WAI の complex images) |

## 3. 媒体の寸法

| マスター | 画素 | 使う先 |
| --- | --- | --- |
| 1.91:1 | 1200×630 | OGP、記事冒頭、LinkedIn のカード(1200×627)、note の見出し画像(1280×670 へ拡大)、Bluesky のカード |
| 1:1 | 1080×1080 | LinkedIn / Bluesky の添付、X の summary |
| 4:5 | 1080×1350 | 縦長の添付(作るなら要素を縦に積み直す) |
| 2:1 | 1280×640 | GitHub の social preview、X の大カード(1.91:1 の上下を 2.3% ずつ切る) |
| 5:7 | 500×700 | Zenn の本の表紙 |
| 節図 | 720×(360〜800) | Zenn の本文(PC 700px、電話 360px で 0.5 倍) |

切り抜きに耐えるのは中央 80% だけ。重要な要素はそこに置きます。

## 4. 図の中の色

| 色 | 意味 |
| --- | --- |
| 藍(ai.800)の面 | 機械・AI が行うこと |
| 丹(human.500)の面 | **人が判定・承認・確認する場所** |
| 墨の点線の環 | 外側の枠組み(既存の制度) |
| 千歳緑 | 採用・成立 |

| 象牙(paper.200)の面 | 囲み・札 |

## 5. 作り方(publishing-hub の例)

```bash
# 1. images/<題材>/<名前>.svg を書く(占位子 {{color.ai.800}} {{font.heading}} を使う)
# 2. 描く
npm run figures:svg            # 変わったものだけ
npm run figures:svg -- --all   # 全部
# 3. 検査(S1〜S6: ソース・PNG・メタ情報の 3 点、ハッシュ、トークンの版、主ラベルの大きさ)
npm run check:diagrams
```

PNG を手で差し替えません。直すのは SVG です。日本語は自動改行されないので `<tspan>` で分けます。これは制約であり、ラベルを短く保つ規律でもあります。

## 6. alt と長い説明

- alt: 「ピットイン方式の全体像。速く回る AI 協調ループの決められた場所に、人が触るピット(仕様承認・独立レビュー)を置く。その外側を事業判断の節目が囲む」のように、1〜2 文で識別する
- 長い説明: 図の直後の本文に、読み順どおりに要素を書く。図だけに情報を持たせない
- 装飾の画像は作らない。装飾に見える画像は、主張と一体でなければ削る

## 7. 生成画像(Gemini など)

概念を伝える生成画像は、図ではなく挿絵として扱います。文字を入れない、ソース(プロンプト・モデル・比率)を記録する、`exempt` に理由つきで登録する。構造を伝える図には使いません。
