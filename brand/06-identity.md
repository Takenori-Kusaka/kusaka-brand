# 06 名乗り ── ワードマークと署名

図形のロゴは持ちません。個人のブランドでは、清潔なワードマークのほうが長く持ちます(Linear の例。外部に守らせるのは名称・余白・色だけ)。

## 1. ワードマーク

| 要素 | 仕様 |
| --- | --- |
| 日本語 | 「日下 武紀」。BIZ UDPGothic 700。字間 0.06em。色は藍(ai.800)か墨(ink.900) |
| 英語 | 「TAKENORI KUSAKA」。同じ書体。字間 0.14em。大文字。補助文の色(ink.600) |
| モノグラム | 「TK」。藍の角丸(半径 22%)の上に生成りの文字。ファビコン・アバターの代替 |
| 最小の余白 | 文字の高さと同じ余白を四方に |
| 最小サイズ | 日本語 14px、英語 10px |

## 2. ハンドルとアバター

- ハンドル「kokorokagami」は、ポッドキャスト(Recalog)とアバターに使う。技術記事と標準の著者名には使わない(著者は実名)
- アバター(digital-garden の `avatar-kokorokagami-*`)は、既存の藍と群青の変種を優先する。写真を使う場面(LinkedIn)は写真

## 3. 署名の行

| 場面 | 行 |
| --- | --- |
| 図の中 | `process-compass / PIT-IN` のように、リポジトリ名か作品名を UDEV Gothic 400、ink.500、幅 / 67 の大きさで隅に |
| 記事の末尾 | 署名を置かない。媒体のプロフィールに任せる |
| スライド | 最終ページに「日下 武紀 ／ Takenori Kusaka」とリンク 3 つまで(GitHub、Zenn、サイト) |
| 名刺 | 日本語の名、英語の名、1 行の肩書き(「現場と経営のあいだを翻訳する設計者」)、URL 1 つ。DIC 特色で藍と丹 |

## 4. 作品の名前

- 標準の通称は「ピットイン方式」(PIT-IN)、正式名称は「AI協調型ソフトウェア開発プロセス標準」(process-compass ADR-0027)。初出で正式名称を併記
- 「〜方式」の作品名は、口頭で通じ、検索で新語として立ち、官公庁の文書に載せて品位を損なわないことを条件に付ける
- 名前は内容を保証しない。名乗ることを適合の根拠にしない

## 5. 所属と見解

- 技術記事・標準・SNS は個人の見解であり、所属組織の公式見解ではないと明記する(サイトの脚注、LinkedIn のプロフィール)
- 所属組織の名前は、プロフィールと経歴にだけ書き、作品の中では書かない
